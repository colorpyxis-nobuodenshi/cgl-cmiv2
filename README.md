## 📂 フォルダ構成 (Directory Structure)

本プロジェクト全体の主要なフォルダ・ファイル構成は以下の通りです。

```text
├── CGLCMIV2.sln                # ソリューションファイル
├── .gitignore                  # Git除外設定ファイル
├── LICENSE                     # ライセンスファイル
├── Config/                     # 【設定・キャリブレーションデータ】
│   ├── appsettings.json        # アプリケーション全体の基本動作設定
│   ├── camera.config.json      # カメラの解像度、露光、ゲイン等のハードウェア設定
│   ├── colorgrade.txt          # カラーグレーディング（色階調・トーン）用の変換データ
│   ├── kisa_matrix.json        # 機器間の個体差を吸収するための器差補正マトリクスパラメータ
│   └── shd.tiff                # シェーディング補正（周辺光量補正）等の基準画像データ
├── CGLCMIV2App/                # 【UIレイヤー】WPFアプリケーション
│   ├── Assets/                 # 画像やスタイルなどのUIリソース
│   ├── Pages/                  # 画面（View/Window/Page）を管理するフォルダ
│   ├── App.xaml / .cs          # アプリケーションのエントリポイント
│   ├── MainWindow.xaml / .cs   # メインウィンドウ
│   └── MessageWindow.xaml      # メッセージダイアログ等のカスタムウィンドウ
└── CGLCMIV2/                   # 【コアロジック】コアロジック・インフラ層（クラスライブラリ）
    ├── Application/            # アプリケーション層（ユースケースとイベントの統括）
    │   ├── AppSettings.cs      # Config内のjson/txt等を読み込み、プログラム内で管理するクラス
    │   ├── Application.cs      # アプリケーションのメイン管理・初期化処理
    │   ├── EventBus.cs         # レイヤー間やコンポーネント間のイベント仲介（疎結合化）
    │   ├── Events.cs           # システム内で発生するイベントの定義
    │   └── UseCases.cs         # ユーザー操作に応じたユースケースのシナリオ定義
    ├── Domain/                 # ドメイン層（ビジネスルール・物理抽象の定義）
    │   ├── Colorimetry.cs      # 色彩計測・色空間処理・器差補正などの核心的な計算ロジック
    │   ├── Device.cs           # ハードウェアデバイスの抽象インターフェース/基底定義
    │   └── Domain.cs           # ドメイン全体の統括・基本ルール定義
    ├── Infra/                  # インフラストラクチャ層（永続化やファイルI/O）
    │   ├── Tiff/               # TIFF画像フォーマットの読み書き・制御フォルダ
    │   └── Infrastructure.cs   # システム基盤・データアクセスの具象実装
    ├── Device/                 # デバイス層（ハードウェアの具象制御）
    │   ├── DFK33UX264.cs       # 産業用カメラ（The Imaging Source製）の制御実装
    │   ├── DS112.cs            # 計測器・センサー等の制御実装
    │   ├── LEDLight.cs         # 照明機器のON/OFFや調光制御実装
    │   ├── RTC21.cs            # 産業用カメラ（池上通信機製）の制御実装
    │   └── DeviceMock.cs       # 実機がない環境で動作検証するためのシミュレータ（モック）
    └── Library/                # ライブラリ層（外部SDK・ネイティブDLLの配置）
        ├── ArtCamSdk_CnvU3l.dll # アートレイ製カメラ等に関するSDK
        ├── rtcApi_x64.dll      # RTC（リアルタイムクロック/コントローラー）制御用API
        ├── ipp*.dll            # Intel Integrated Performance Primitives（画像処理高速化ライブラリ）
        └── DiamondContour.*    # 輪郭形状計測・画像解析等の外部ライブラリ
```

## 🏛️ アーキテクチャ概要 (Architecture)

本システムは、ハードウェアの変更やOSのアップデート、UIの刷新に対して柔軟に対応できるよう、**ドメイン駆動設計（DDD）およびクリーンアーキテクチャ（オニオンアーキテクチャ）の思想を取り入れた階層化アーキテクチャ**を採用しています。

特に「実機に依存しない開発（テスタビリティの担保）」と「高度な色彩管理・キャリブレーション処理の独立」に主眼を置いて設計されています。

### 🛠️ 設計の特徴

1. **厳密なキャリブレーション・外部設定の分離 (`Config/`)**
   カメラの個体差や環境光の影響を補正するためのデータ（`kisa_matrix.json`, `shd.tiff` など）をコードから完全に分離し、外部ファイルとして管理しています。これらは `Application/AppSettings.cs` を通じてシステムに読み込まれ、`Domain/Colorimetry.cs` での正確な色彩計算・補正処理に適用されます。
2. **実機に依存しない開発（DeviceMockの導入）**
   `Domain/Device.cs` でデバイスの共通インターフェースを定義し、`Device/DeviceMock.cs` を用意することで、カメラやセンサーなどの実機が接続されていない環境でもシステム全体のシミュレーションおよび自動テストが可能です。
3. **イベント駆動による疎結合（EventBusの採用）**
   `Application/EventBus.cs` を媒介にすることで、UI層やハードウェア層が相互に直接依存（密結合）することなく、状態の変化（カメラのキャプチャ完了、エラー発生など）を安全に通知し合える設計になっています。

### 各レイヤーの役割

#### 1. UI レイヤー (`CGLCMIV2App`)
* **役割**: WPFによるユーザーインターフェース表示。
* **解説**: ユーザーの入力を受け付け、背後の Application 層に処理を委ねます。UIコントロールの表示制御や画面遷移のみを担当します。

#### 2. アプリケーション層 (`CGLCMIV2/Application`)
* **役割**: ユースケースの実現と、システム内のイベント・設定の調整。
* **解説**: `UseCases.cs` が、UIからの要求に応じてドメインロジックやデバイス制御の実行順序を組み立てます。また、`Config/` 配下の json や tiff などの設定・補正データを `AppSettings.cs` で一元管理します。

#### 3. ドメイン層 (`CGLCMIV2/Domain`)
* **役割**: システムの核心となるビジネスルール・物理抽象の定義。
* **解説**: 他のすべての層から独立しています。`Colorimetry.cs` による器差補正・色彩計算ロジックや、`Device.cs` によるハードウェアの抽象定義など、このシステムにおいて最も重要かつ変更頻度の低いロジックが配置されます。

#### 4. デバイス層 (`CGLCMIV2/Device`)
* **役割**: 物理ハードウェア（カメラ、センサー、照明、RTC）の具象制御。
* **解説**: ドメイン層で定義された `Device` インターフェースを実装し、`Library/` 内の各種SDK（DLL）を叩いて実際の機器を動かします。`camera.config.json` に基づいたカメラパラメータの適用などもここで行われます。

#### 5. インフラストラクチャ層 (`CGLCMIV2/Infra`)
* **役割**: データの永続化やファイルシステムへのアクセス。
* **解説**: 本システムでは特に `Tiff/` フォルダ配下での画像ファイルの保存・読み込み処理など、周辺機器ではなく「システム基盤」に関わる具象処理を担当します。

## 💻 動作・開発環境 (Requirements)
* **リリースバージョン**: `Release/2.1.0` / `2.1.1` 系統
* **ターゲットフレームワーク**: 
  * `CGLCMIV2App` (WPF): `.NET 8.0` (`net8.0-windows10.0.22621.0`)
  * `CGLCMIV2` (コア): `.NET 8.0` (`net8.0`)
* **リリースバージョン**: `Release/2.0.0` 系統
* **ターゲットフレームワーク**: 
  * `CGLCMIV2App` (WPF): `.NET 5.0` (`net5.0-windows)
  * `CGLCMIV2` (コア): `.NET 5.0` (`net5.0`)
* **プラットフォーム / アーキテクチャ**: `x64` / `AnyCPU` (ネイティブDLLを含むため、原則 **x64** でのビルド・実行を推奨)
* **特記事項**: 外部SDK連携および画像・色彩の高速処理のため、プロジェクト全体で **アンセーフコード (`AllowUnsafeBlocks`)** を許可しています。
* **主要な外部依存パッケージ**:
  * **カメラ制御**: `ic4dotnet` (The Imaging Source 最新SDK)
  * **画像処理**: `OpenCvSharp4` (OpenCV ラッパー)
  * **UIフレームワーク**: `MaterialDesignThemes` (マテリアルデザイン)
  * **その他**: `System.IO.Ports` (シリアル通信用), `System.Reactive` (非同期・イベント処理用), `Serilog` (ロギング)
